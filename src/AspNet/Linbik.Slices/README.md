# Linbik.Slices

**Vertical-slice infrastructure for ASP.NET Core Minimal API.**  
Zero external dependencies. Compile-time endpoint registration via source generator.

---

## What is Linbik.Slices?

`Linbik.Slices` implements the **Vertical Slice Architecture** pattern on top of ASP.NET Core Minimal API.

Instead of spreading a feature across multiple layers (Controllers → Services → Repositories), each feature lives in a **single self-contained class** — a *slice* — that owns its request, response, validation logic, and business logic together.

The bundled **source generator** reads the `[LinbikSlice]` attribute at compile-time and automatically produces:
- Minimal API endpoint mappings (`MapGet`, `MapPost`, …)
- DI registrations for every handler and validator
- OpenAPI metadata (tags, operation IDs, response schemas)
- Flow-based authorization metadata

No reflection at startup. No manual wiring.

---

## At a Glance

```
HTTP Request
     │
     ▼
[LinbikSlice endpoint — generated by source generator]
     │
     ▼
ILinbikSender.Send(request)
     │
     ├── ILinbikValidator<TRequest>?   ← optional; skipped if not registered
     │       └── validation fails → 400 Result<TResponse>.Fail(LError.Validation(...))
     │
     └── ILinbikHandler<TRequest, TResponse>   ← required
             └── returns Result<TResponse>
                         │
                         ▼
               LinbikEndpoint.ToHttp()
                         │
                         ▼
               LBaseResponse<TResponse>  (200 / 400 / 403 / 404 / 409)
```

## Quick Start

### 1. Register and map slices in `Program.cs`

```csharp
// Register ILinbikSender + all generated handler/validator DI entries
builder.Services.AddLinbikSlices();

// Optional: global JSON parse error handler → LBaseResponse contract
builder.Services.AddLinbikSliceExceptionHandling();

var app = builder.Build();

app.UseLinbikSliceExceptionHandling(); // must come early, before routing
app.MapLinbikSlices();                 // maps all [LinbikSlice] endpoints
```

### 2. Write a slice

Create a single file per feature. Everything lives inside one `static partial class`.

**Minimal slice (no validation, public endpoint):**

```csharp
using Linbik.Slices;
using Linbik.Slices.Results;

[LinbikSlice("/api/arithmetic/add", Tag = "Arithmetic")]
[LFlowPublic]
public static partial class Add
{
    public sealed record Request(double A, double B) : ILinbikRequest<Response>;

    public sealed record Response(double Result);

    public sealed class Handler : ILinbikHandler<Request, Response>
    {
        public ValueTask<Result<Response>> HandleAsync(Request request, CancellationToken cancellationToken)
            => Result.Ok(new Response(request.A + request.B)).AsValueTask();
    }
}
```

**Slice with validation (restricted to specific flows):**

```csharp
using Linbik.Slices;
using Linbik.Slices.Results;

[LinbikSlice("/api/arithmetic/divide", Tag = "Arithmetic")]
[LFlow(LinbikFlow.Self, LinbikFlow.Application)]
public static partial class Divide
{
    public sealed record Request(double A, double B) : ILinbikRequest<Response>;

    public sealed record Response(double Result);

    public sealed class Validator : ILinbikValidator<Request>
    {
        public ValueTask<LValidationResult> ValidateAsync(Request request, CancellationToken cancellationToken)
            => LValidation.For(request)
                .Ensure(static x => x.B != 0, field: "B", message: "The divisor (B) cannot be zero.")
                .BuildAsync();
    }

    public sealed class Handler : ILinbikHandler<Request, Response>
    {
        public ValueTask<Result<Response>> HandleAsync(Request request, CancellationToken cancellationToken)
            => Result.Ok(new Response(request.A / request.B)).AsValueTask();
    }
}
```

## Core Abstractions

### `ILinbikRequest<TResponse>`

Marks a type as a slice request. The `TResponse` type parameter defines the success payload type that the handler returns.

```csharp
public sealed record CreateOrderRequest(Guid ProductId, int Quantity) : ILinbikRequest<CreateOrderResponse>;
```

### `ILinbikHandler<TRequest, TResponse>`

Contains the business logic for a slice. Handlers are **pure** — they never throw exceptions for domain failures; they return `Result<TResponse>` instead.

```csharp
public sealed class Handler : ILinbikHandler<CreateOrderRequest, CreateOrderResponse>
{
    public ValueTask<Result<CreateOrderResponse>> HandleAsync(
        CreateOrderRequest request, CancellationToken cancellationToken)
    {
        // ...
        return Result.Ok(new CreateOrderResponse(orderId)).AsValueTask();
    }
}
```

### `ILinbikValidator<TRequest>` *(optional)*

Pre-handler validation. If registered, the pipeline runs it before calling the handler. If validation fails, the handler is **never called** — the pipeline returns a `400` response immediately.

Implementing a validator is entirely optional. If no `ILinbikValidator<TRequest>` is registered for a request type, the pipeline skips validation silently.

```csharp
public sealed class Validator : ILinbikValidator<CreateOrderRequest>
{
    public ValueTask<LValidationResult> ValidateAsync(
        CreateOrderRequest request, CancellationToken cancellationToken)
        => LValidation.For(request)
            .Ensure(x => x.Quantity > 0, field: "Quantity", message: "Quantity must be positive.")
            .BuildAsync();
}
```

### `ILinbikSender`

The dispatcher. Resolves and runs the `validator → handler` pipeline for a given request. Registered as `Scoped`. The type-specific wrapper objects are cached per request type so reflection cost is paid only once.

```csharp
// Injected automatically into generated endpoint delegates
var result = await sender.Send(request, cancellationToken);
```

## Result and Error Types

### `Result<T>`

An immutable success/failure envelope. Handlers return this instead of throwing exceptions.

```csharp
// Success
return Result.Ok(new Response(...));

// Failure
return Result<Response>.Fail(LError.NotFound("Order not found."));

// Implicit conversions are also available
return new Response(...);          // implicit Ok
return LError.NotFound("...");     // implicit Fail
```

### `LError`

Carries the HTTP status code alongside human-readable context. Built-in factories:

| Factory | Status | Title |
|---|---|---|
| `LError.Validation(message, errors?)` | 400 | `validation_failed` |
| `LError.BadRequest(title, message)` | 400 | custom |
| `LError.Forbidden(message)` | 403 | `forbidden` |
| `LError.NotFound(message)` | 404 | `not_found` |
| `LError.Conflict(message)` | 409 | `conflict` |

### `LValidation`

A lightweight fluent validation builder. No external dependencies.

```csharp
LValidation.For(request)
    .Ensure(x => x.Name.Length > 0, field: "Name", message: "Name is required.")
    .Ensure(x => x.Age >= 18,        field: "Age",  message: "Must be 18 or older.")
    .BuildAsync(); // returns ValueTask<LValidationResult>
```

## Attributes

### `[LinbikSlice(pattern)]`

Marks a class as a vertical slice. The source generator scans all types with this attribute and emits endpoint mapping + DI registration code at compile-time.

```csharp
[LinbikSlice("/api/orders", Method = "POST", Tag = "Orders",
    Summary = "Create a new order", Description = "Creates an order for the given product.")]
```

| Property | Default | Description |
|---|---|---|
| `pattern` | *(required)* | Route pattern, e.g. `/api/orders/{id}` |
| `Method` | `"POST"` | HTTP verb: `GET`, `POST`, `PUT`, `PATCH`, `DELETE` |
| `Tag` | slice class name | OpenAPI tag |
| `Summary` | — | OpenAPI operation summary |
| `Description` | — | OpenAPI operation description |

> **Note:** `GET`, `DELETE`, and `HEAD` endpoints bind request properties from the **query string** (`[AsParameters]`). `POST`, `PUT`, and `PATCH` endpoints bind from the **JSON body** (`[FromBody]`).

### `[LFlowPublic]`

Marks the endpoint as publicly accessible — no Linbik-Flow header required.

```csharp
[LinbikSlice("/api/health")]
[LFlowPublic]
public static partial class HealthCheck { ... }
```

### `[LFlow(params LinbikFlow[] flows)]`

Restricts the endpoint to one or more named authorization flows. `LinbikFlow` (`Self`, `Delegated`, `Application`) lives right in the `Linbik.Slices` namespace you already import — no extra `using` or magic strings, and your IDE autocompletes the valid choices. The source generator embeds this as `LFlowAuthorizeAttribute` endpoint metadata, which `LinbikFlowEndpointFilter` enforces at runtime.

```csharp
[LinbikSlice("/api/admin/users")]
[LFlow(LinbikFlow.Self)]   // only the "self" flow may call this
public static partial class GetUsers { ... }
```

Parametreless `[LFlow]` = any authenticated flow is accepted.

> ⚠️ **`[LFlow]` requires an API Gateway.** It trusts the `Linbik-Flow` header — a value that is only safe to trust because a Gateway strips any client-supplied `Linbik-*` headers and re-writes it from the route's authenticated claims (see `ARCHITECTURE.md`). If your service is reachable directly (no Gateway in front, e.g. a monolith or a service you call without YARP), that header is either missing (every request gets 401) or, worse, spoofable by any caller. Use `[LAuthorizeFlow(...)]` instead for those architectures.

### `[LAuthorizeFlow(params LinbikFlow[] flows)]`

For services that are **not** behind an API Gateway (or that want defense-in-depth regardless). Instead of trusting a header, `LinbikAuthorizeFlowEndpointFilter` tries each allowed flow's actual PASETO/JWT scheme (`LinbikDefaults.ClientScheme` / `DelegatedScheme` / `ApplicationScheme` — registered by `Linbik.JwtAuthManager`/`Linbik.PasetoAuthManager`/`Linbik.Server`) in order and stops at the first one that authenticates — a request is only ever valid for one flow, so there's no need to keep checking once one succeeds. Schemes that aren't registered on the service (e.g. you only added `Linbik.JwtAuthManager` for Self but not `Linbik.Server` for Delegated/Application) are skipped gracefully instead of throwing, and the `401` response tells you exactly what happened:

```json
{ "isSuccess": false, "friendlyMessage": { "title": "unauthorized", "message": "Identity could not be verified for flow(s): Self. Flow(s) Delegated, Application are not configured on this service (missing authentication scheme registration)." } }
```

```csharp
[LinbikSlice("/api/admin/users")]
[LAuthorizeFlow(LinbikFlow.Self)]   // only requests authenticated via ClientScheme (cookie) pass
public static partial class GetUsers { ... }
```

Parametresiz `[LAuthorizeFlow]` = any of the three schemes is accepted. A slice may declare **only one** of `[LFlow]`, `[LFlowPublic]`, `[LAuthorizeFlow]` — combining them is a compile error (`LINBIK004`).

> **LINBIK001 (compile-time error):** Every `[LinbikSlice]` type **must** declare exactly one of `[LFlowPublic]`, `[LFlow(...)]` or `[LAuthorizeFlow(...)]`. Omitting all three is a deny-by-default enforcement and produces a compiler error.

## Source Generator

The included incremental source generator (`LinbikSliceGenerator`) reads `[LinbikSlice]` attributes at compile time and emits a single file — `LinbikSlicesRegistry.g.cs` — into the consuming project:

```csharp
// Generated output (simplified)
public static class LinbikSlicesRegistry
{
    public static IServiceCollection AddLinbikSlices(this IServiceCollection services)
    {
        Linbik.Slices.LinbikSlicesServiceCollectionExtensions.AddLinbikSender(services);
        services.AddScoped<ILinbikHandler<Add.Request, Add.Response>, Add.Handler>();
        services.AddScoped<ILinbikHandler<Divide.Request, Divide.Response>, Divide.Handler>();
        services.AddScoped<ILinbikValidator<Divide.Request>, Divide.Validator>();
        // ...
        return services;
    }

    public static IEndpointRouteBuilder MapLinbikSlices(this IEndpointRouteBuilder app)
    {
        app.MapPost("/api/arithmetic/add", ([FromBody] Add.Request request, ILinbikSender sender, CancellationToken ct)
            => LinbikEndpoint.Handle<Add.Request, Add.Response>(request, sender, ct))
            .WithTags("Arithmetic")
            .WithName("Add")
            .Produces<LBaseResponse<Add.Response>>(200)
            .Produces<LBaseResponse<Add.Response>>(400);
        // ...
        return app;
    }
}
```

The generator only emits output when at least one valid slice exists in the project. Projects without any `[LinbikSlice]` types produce no generated file.

## Pipeline Execution Order

```
ILinbikSender.Send(request)
  1. Resolve ILinbikValidator<TRequest> via GetService  (null-safe — optional)
  2. If validator found → run ValidateAsync
       └── validation errors → return Result<TResponse>.Fail(LError.Validation(...))
  3. Resolve ILinbikHandler<TRequest, TResponse> via GetRequiredService  (required)
  4. Run HandleAsync → return Result<TResponse>
```

- Validator is **always optional**. Missing registration = skipped silently.
- Handler is **always required**. Missing registration = `InvalidOperationException` at runtime (the source generator prevents this at compile time via the LINBIK002 diagnostic).
- Wrapper instances are cached in a `ConcurrentDictionary` keyed by request type — reflection runs only on the first call per type.

## HTTP Response Contract

All endpoints return `LBaseResponse<TResponse>` — a unified envelope defined in `Linbik.Core`:

```json
// 200 OK — success
{ "isSuccess": true, "data": { ... } }

// 400 Bad Request — validation failure
{ "isSuccess": false, "title": "validation_failed", "message": "One or more validation errors occurred." }

// 404 Not Found
{ "isSuccess": false, "title": "not_found", "message": "Order not found." }
```

The generator automatically declares all response shapes (200, 400, 403, 404, 409) in the OpenAPI document via `.Produces<LBaseResponse<TResponse>>(statusCode)`.

## Exception Handling

Register the optional JSON parse error handler to convert malformed request bodies into the standard `LBaseResponse` contract instead of the default ASP.NET Core problem details response:

```csharp
builder.Services.AddLinbikSliceExceptionHandling();
// ...
app.UseLinbikSliceExceptionHandling(); // before app.UseRouting()
```

## File Structure Convention

```
Features/
├── Orders/
│   ├── CreateOrder.cs    ← [LinbikSlice] class: Request + Response + Validator + Handler
│   ├── GetOrder.cs
│   └── CancelOrder.cs
└── Products/
    ├── ListProducts.cs
    └── GetProduct.cs
```

One file per feature. All related types (request, response, validator, handler) are nested inside the slice class. The source generator discovers them automatically.

## Diagnostics

| ID | Severity | Trigger | Message |
|---|---|---|---|
| `LINBIK001` | Error | `[LinbikSlice]` without `[LFlow]`, `[LFlowPublic]`, or `[LAuthorizeFlow]` | Deny-by-default: no flow declared — access flows must be explicit (use `[LFlowPublic]` for public endpoints) |
| `LINBIK002` | Error | `[LinbikSlice]` without a nested `Request` (`ILinbikRequest<>`) and/or `Handler` (`ILinbikHandler<,>`) | Missing required inner types |
| `LINBIK003` | Warning | A project contains no `[LinbikSlice]`-marked types at all | `AddLinbikSlices`/`MapLinbikSlices` were not generated for this project — add a slice or remove those calls |
| `LINBIK004` | Error | `[LinbikSlice]` carries more than one of `[LFlow]`, `[LFlowPublic]`, `[LAuthorizeFlow]` | Conflicting flow declaration — only one of these attributes may be used per slice |

## Problem Statement

`examples/AspNet.Gateway/` altında, **.NET 10** ile Linbik'i bir API gateway olarak
kullanmanın referans örneği olacak bir proje istiyoruz. Senaryo:

- Auth tek noktada (gateway). Downstream mikro servislerde `[Authorize]` yok.
- Her gelen istekte gateway, JWT'yi parse eder, allowlist'teki claim'leri
  `X-Linbik-*` header'larına yazar ve downstream'e iletir.
- Gelen istekte zaten var olan `X-Linbik-*` header'ları **önce silinir** ki
  dışarıdan spoof edilemesin.
- Linbik servisleri yalnızca **Self** modunda. Ekstra entegrasyon servisi
  kullanmak isteyen tüketiciler için **Delegated** ve **Apps** katmanları da olur.
- Üç scheme: `LinbikAuthorize` (Self), `LinbikDelegatedAuthorize` (Delegated),
  `LinbikApplicationAuthorize` (Apps) — Linbik.Core'da hazır.
- OpenAPI dokümanları gateway'de toplanır. Self/Delegated/Apps üç ayrı doküman.
  Self prod'da kapalı, diğer ikisi açık (default).
- Gateway kullanıldığında Linbik.YARP'taki yönlendirme görevi gateway'e taşınır.

## What Makes This Cool

Linbik'in bugünkü kütüphane setine "edge gateway" pattern'ını net biçimde gösteren
bir referans yok. Mikro servisleri auth'tan tamamen arındırıp gateway'i tek
otorite yapmak; downstream'lerin kod tarafında `User.Claims` yerine `Request.Headers`
okuması; OpenAPI'yi audience'a göre üç gruba ayırıp prod'da Self'i kapatmak —
bunların hepsi tek bir runnable örnekte birleşince Linbik'in nasıl
"production-ready gateway" olarak konumlandığı görünür hale geliyor.

## Constraints

- .NET 10. `Microsoft.AspNetCore.OpenApi` (Swashbuckle değil).
- Linbik.Core, Linbik.JwtAuthManager mevcut paketler, olduğu gibi kullanılır.
- Linbik.YARP **kullanılmaz** (outbound token injection için tasarlanmış,
  gateway senaryosu inbound claim extraction).
- Sample bir paket çıkarmaz; gateway parçaları sample içinde yerel sınıflar.

## Premises (onaylandı)

1. **Gateway = tek auth çıtası.** Downstream `[Authorize]` çalıştırmaz, sadece
   `X-Linbik-*` header'larına bakar. Header spoof'a karşı koruma: **network
   izolasyonu varsayımı** (downstream sadece gateway'in erişebileceği ağda).
   _Risk_: gateway bypass edilirse downstream spoof'a açık. Üretim notu doc'a girer.
2. **Allowlist + `X-Linbik-*` prefix.** Tüm prefix gelen istekte silinir, sonra
   JWT parse'tan sonra allowlist'teki claim'ler yeniden yazılır.
3. **Endpoint ayrımı route prefix ile.** `/self/**` → LinbikScheme,
   `/delegated/**` → LinbikDelegated, `/apps/**` → LinbikApplication.
4. **OpenAPI N:N üyelik.** Bir endpoint birden fazla dokümanda görünebilir
   (örn. hem Self hem Delegated). Üyelik kaynağı: downstream operation'da
   `x-linbik-audiences` extension varsa o, yoksa cluster metadata'sındaki
   default audience.
5. **Linbik.YARP yerine** YARP'ı doğrudan + yerel transform. YARP zorunluluk
   değil; engine swap'a açık tutmak için transform ayrı sınıf.
6. **Sample sadece sample.** Linbik.Gateway paketi şimdi çıkmıyor.

## Approaches Considered

### Approach A — YARP + inline gateway pipeline (chosen)
Sample içinde 3 scheme + 3 policy, YARP route config (appsettings), tek
inbound transform sınıfı (header sanitize + claim injection), 3 OpenAPI
dokümanı + downstream aggregator.

### Approach B — `IHttpForwarder` + elden routing
YARP soyutlamasını atla, `app.Map` ile elden forward. Edge case (streaming,
WS, header forward) yükü artar.

### Approach C — Şimdi `Linbik.Gateway` paketi çıkar
Premature abstraction riski. Pattern olgunlaşmadan paketleme.

### Auth Pipeline (Gateway)

`GatewayAuthenticationExtensions.AddLinbikGatewayAuthentication(...)`:

- **LinbikScheme** (Self): cookie `authToken` → HS256.
  `Linbik.JwtAuthManager.AddLinbikJwtAuth(...)` zaten bunu kuruyor; gateway aynı
  extension'ı çağırır.
- **LinbikDelegated**: `Authorization: Bearer` → RS256, user-context claim'leri
  bekler (`sub`, `name`, `preferred_username`, `azp`).
- **LinbikApplication**: `Authorization: Bearer` → RS256, S2S claim'leri
  (`source_service_id`, `source_package`, `target_package`, `role`).

Üç policy: `SelfPolicy`, `DelegatedPolicy`, `AppsPolicy` — her biri tek scheme
zorunlu kılar (`RequireAuthenticatedUser` + `AddAuthenticationSchemes`).

> Not: 3 scheme'i route prefix'inden seçmek için YARP'ın `AuthorizationPolicy`
> route property'si kullanılır. Her route appsettings'te
> `"AuthorizationPolicy": "SelfPolicy"` belirtir.

### Header Sanitize + Claim Injection

`ClaimToHeaderTransform : IRequestTransform`. İki adım:

1. **Sanitize.** Gelen istekteki `LinbikGatewayDefaults.HeaderPrefix` (`X-Linbik-`)
   ile başlayan tüm header'ları proxy isteğinden sil. Authorization header da
   düşer (downstream'in JWT görmesine gerek yok).
2. **Inject.** `HttpContext.User.Claims` üzerinden allowlist:

| Claim | Header |
|---|---|
| `sub` | `X-Linbik-Sub` |
| `name` | `X-Linbik-Name` |
| `preferred_username` | `X-Linbik-Username` |
| `azp` | `X-Linbik-Azp` |
| `scope` | `X-Linbik-Scope` |
| `role`/`roles` | `X-Linbik-Roles` (virgüllü) |
| `source_service_id` | `X-Linbik-Source-Service` |
| `source_package` | `X-Linbik-Source-Package` |
| `target_package` | `X-Linbik-Target-Package` |
| `aud` | `X-Linbik-Audience` |

Ek olarak meta:
- `X-Linbik-Scheme`: hangi scheme ile doğrulandı (self|delegated|apps)
- `X-Linbik-Gateway`: bu gateway'in adı (audit)

Allowlist `LinbikGatewayDefaults` içinde `static readonly` dict. Genişletme
gereken müşteriler `appsettings.json`'da `LinbikGateway:ClaimHeaderMap` ile
override edebilir.

### YARP Routing

`appsettings.json`:

```json
{
  "ReverseProxy": {
    "Routes": {
      "self-echo": {
        "ClusterId": "echo-cluster",
        "AuthorizationPolicy": "SelfPolicy",
        "Match": { "Path": "/self/echo/{**catchall}" },
        "Transforms": [ { "PathRemovePrefix": "/self" } ],
        "Metadata": {
          "linbik:scheme": "self",
          "linbik:audiences": "self"
        }
      },
      "delegated-payments": {
        "ClusterId": "payments-cluster",
        "AuthorizationPolicy": "DelegatedPolicy",
        "Match": { "Path": "/delegated/payments/{**catchall}" },
        "Transforms": [ { "PathRemovePrefix": "/delegated" } ],
        "Metadata": {
          "linbik:scheme": "delegated",
          "linbik:audiences": "delegated"
        }
      },
      "apps-sync": {
        "ClusterId": "payments-cluster",
        "AuthorizationPolicy": "AppsPolicy",
        "Match": { "Path": "/apps/payments/{**catchall}" },
        "Transforms": [ { "PathRemovePrefix": "/apps" } ],
        "Metadata": {
          "linbik:scheme": "apps",
          "linbik:audiences": "apps"
        }
      }
    },
    "Clusters": {
      "echo-cluster":     { "Destinations": { "d1": { "Address": "http://localhost:5101/" } } },
      "payments-cluster": { "Destinations": { "d1": { "Address": "http://localhost:5102/" } } }
    }
  }
}
```

Program.cs (özet):

```csharp
builder.Services.AddLinbik(...)
    .AddLinbikJwtAuth(builder.Configuration.GetSection("Linbik:JwtAuth"));
builder.Services.AddLinbikGatewayAuthentication(builder.Configuration);
builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"))
    .AddTransforms(b => b.RequestTransforms.Add(new ClaimToHeaderTransform()));

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();
app.MapLinbikOpenApiAggregator();
app.MapReverseProxy();
```

### OpenAPI Aggregation (3 doküman, N:N endpoint üyeliği)

.NET 10'da `Microsoft.AspNetCore.OpenApi` paketi yerleşik. Gateway 3 doküman
serve eder:

- `GET /openapi/self.json`
- `GET /openapi/delegated.json`
- `GET /openapi/apps.json`

`OpenApiAggregator` periyodik (veya on-demand cache, 60sn TTL) downstream'lerin
`/openapi/v1.json`'unu çeker. Cluster konfigürasyonu hangi downstream'in hangi
URL'sini sorgulayacağını bilir (cluster metadata `linbik:openapi-path`,
default `/openapi/v1.json`).

**Audience eşlemesi (N:N için kritik):**

Her downstream operation'ı için sıralı karar:
1. Operation'da `x-linbik-audiences: [self, delegated]` extension varsa → onu kullan.
2. Yoksa → route metadata'sındaki `linbik:audiences` (virgüllü liste) → onu kullan.
3. Yoksa → route prefix'inden türet (`/self/*` → `[self]`, vs).

Bu sırayla operation hangi doküman(lar)a girer kararlaştırılır. Bir endpoint
hem `[self, delegated]` listesinde ise iki dokümana da yazılır (path rewrite
ile: `self.json`'da `/self/...`, `delegated.json`'da `/delegated/...`).

`AudienceFilter` aggregator içinde, her operasyon için bu kararı uygular ve
çıktı dokümanına filtreleyerek koyar.

**Default visibility:**

- `IWebHostEnvironment.IsProduction()` ise `/openapi/self.json` 404 döner.
- `appsettings.json` üzerinden override:

```json
"LinbikGateway": {
  "OpenApi": {
    "Self":      { "ExposeInProduction": false },
    "Delegated": { "ExposeInProduction": true },
    "Apps":      { "ExposeInProduction": true }
  }
}
```

UI: `Scalar.AspNetCore` veya `Swashbuckle.AspNetCore.SwaggerUI` (sadece UI için)
3 ayrı sayfa. Sample'da `Scalar` tercih edilir; .NET 10 OpenAPI ile native uyumlu.

### Downstream.Sample

Auth yok. `[Authorize]` yok. Tek bir controller `EchoController` `Request.Headers`
üzerinden `X-Linbik-Sub`, `X-Linbik-Scope` vs. okur ve döner. Bu ile downstream
servisin gateway'e nasıl güvenip header okuduğu örneklenir. Ayrıca downstream
kendi `openapi.json`'unu yayınlar; operation'lara `x-linbik-audiences` extension
örneği eklenir (OpenAPI document transformer).

## Open Questions

1. **OpenAPI cache TTL ne olmalı?** 60sn şimdilik, prod'da config'le ayarlanır.
2. **Downstream openapi.json'a nasıl ulaşacağız üretimde?** Cluster destination
   URL + relative path varsayımı şimdilik yeterli. Service discovery konusu sample
   kapsamı dışı.
3. **Refresh token akışı gateway'de mi olacak?** Şu an out-of-scope; Self için
   cookie zaten Linbik.JwtAuthManager tarafından yönetiliyor.
4. **Rate limit gateway'de mi?** `Linbik.JwtAuthManager.RateLimitExtensions`
   mevcut; sample'a opsiyonel bir kayıt eklenir (kapalı, README'de "açmak için"
   notu).

## Success Criteria

- `dotnet run` ile gateway 5100, downstream 5101'de ayağa kalkar.
- `curl` ile cookie auth → `/self/echo/hello` → downstream `X-Linbik-Sub` görür,
  döner.
- Bearer token ile `/delegated/...` → `X-Linbik-Username` downstream'de görünür.
- S2S token ile `/apps/...` → `X-Linbik-Source-Package` downstream'de görünür.
- Gelen istekteki manipüle `X-Linbik-Sub: attacker` → downstream'de **görünmez**
  (gateway silmiş, yenisini yazmış).
- `/openapi/self.json`, `/openapi/delegated.json`, `/openapi/apps.json` ayrı
  içerik döner. `x-linbik-audiences: [self, delegated]` olan bir downstream
  endpoint'i hem `self.json`'da hem `delegated.json`'da görünür.
- `ASPNETCORE_ENVIRONMENT=Production` ile `/openapi/self.json` 404, diğer ikisi
  200.
- README adım adım manuel test komutlarını içerir.

## Production Notes (sample kapsamı dışı ama README'ye not)

- **Header spoof riski**: Downstream'ler **sadece** gateway erişiminde olacak
  şekilde ağ izolasyonu (private VNet, internal LB, mTLS, K8s NetworkPolicy).
  Aksi halde saldırgan downstream'i doğrudan çağırıp `X-Linbik-Sub`'u spoof'lar.
- **Üretime geçerken** gateway → downstream arası kısa ömürlü HMAC imzalı
  internal JWT eklenmesi şiddetle önerilir (header'lara ek olarak `X-Linbik-Sig`
  ile claim'lerin bütünlüğü doğrulanır). Bu, ileri sürüm Linbik.Gateway
  paketinin core değeri olabilir.
- **Self prod'da kapalı** OpenAPI default'u: dahili API'nin attack surface'ini
  azaltır.

## Reviewer Concerns

Adversarial review bu environment'ta otomatik koşturulamadı (gstack subagent
araçları Unix-only). Manuel kontrol noktaları:

- **N:N OpenAPI birleştirme** path collision yapabilir: aynı path iki dokümanda
  farklı prefix ile (`/self/payments/x` vs `/delegated/payments/x`) — aggregator
  prefix'i route'a göre yeniden yazmalı.
- **Allowlist'in genişletilmesi** appsettings'ten override edildiğinde validator
  unutulmamalı (yanlış case'li header isimleri sessizce düşer).
- **YARP `AuthorizationPolicy` ile birden fazla policy** birleştirilemez; bir
  endpoint sadece tek policy alabilir. Bir endpoint hem self hem delegated
  doküman üyeliği OpenAPI seviyesinde mümkün ama **runtime'da iki ayrı route**
  ile (her biri kendi policy'sini taşıyarak) ifade edilmeli — bu noktayı README
  ve sample açıkça göstermeli.

## What I noticed about how you think

- "yarp olmasına gerek yok daha iyi çözüm varsa onu da kullanabiliriz" dediniz —
  pattern'a değil amaca tutunuyorsunuz. Bu, sample'ın paket haline geleceği
  zaman engine swap'a saygılı bir tasarım çıkmasını sağlıyor.
- "bazı endpointler birden fazla dokümanda bulunabilecek" — N:N üyeliği baştan
  fark etmek, çoğu kişinin OpenAPI aggregator'a başladıktan sonra gördüğü bir
  şey. Bu detay gateway'in en kritik tasarım kararını şekillendirdi.
- "self prod ortamda kapalı diğerleri açık olmalı" — attack surface bilinciyle
  default seçiyorsunuz. Sample'ı doğrudan üretim default'larıyla göstermek
  pattern'in benimsenmesini kolaylaştıracak.
- Header spoof'a karşı en hızlı yolu (network izolasyonu) seçtiniz, ama soruyu
  duyduğunuzda risk hemen netti. Sample bu trade-off'u README'de açıkça
  yazdığında, paket sürümünde HMAC internal JWT katmanı doğal sonraki adım
  olarak görünür.
